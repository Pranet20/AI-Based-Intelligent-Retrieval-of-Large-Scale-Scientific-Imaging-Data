# Final Platform Demonstration Runbook
**Platform**: AI-Powered Scientific Image Data Management Platform  
**Target Audience**: Academic Reviewers, Evaluators, and Scientific Collaborators  
**Estimated Duration**: 5 – 10 Minutes  
**Execution Environment**: Local Docker Compose Stack  

---

## 1. Demonstration Objective
This runbook provides a scripted, sequential demonstration workflow illustrating the end-to-end capabilities of the platform: from cryptographic image ingestion and DINOv2 visual embedding extraction to sub-millisecond similarity search, automated quality-risk triage, and human-in-the-loop curation recording.

   - Navigate to `http://localhost:3000` to display the responsive React web dashboard.

## 3. Core Demonstration Sequence (Minutes 2–8)

### Step 1: Authentication & RBAC (Minute 2)
- Demonstrate secure JWT-based authentication.
- Register an account with role `SCIENTIST` or log in using administrative credentials.
- Point out RBAC UI adaptations (curator queue and admin audit trails dynamically revealed based on role claims).

### Step 2: Scientific Project Creation (Minute 3)
- In the dashboard, click **"New Project"**.
- Enter:
  - **Project Name**: `High-Entropy Alloy Phase Analysis`
  - **Description**: `Investigation of grain boundary precipitation under varying accelerating voltages.`
- Show that project creation generates an isolated workspace UUID with zero cross-tenant contamination.

### Step 3: Ingestion, Validation & Metadata Extraction (Minute 4)
- Navigate to the **Ingestion Workbench**.
- Upload a sample electron micrograph (`.tif` or `.png`).
- Highlight automated backend actions:
  - **Magic Byte Validation**: Verifies genuine image headers, rejecting disguised files.
  - **Cryptographic Hashing**: Streaming SHA-256 digest computed on the fly.
  - **Metadata Extraction**: Instrument accelerating voltage ($20.0\text{ kV}$), magnification ($50,000\times$), detector mode (`BSE`).
- **Demonstrate Idempotency**: Re-upload the exact same image. The system recognizes the existing SHA-256 digest, returning the existing image entity without duplicating storage.

### Step 4: Quality-Risk Profiling & Novelty Scoring (Minute 5)
- Inspect the newly ingested image in the **Detail Inspector**:
  - **Laplacian Variance (Sharpness)**: Quantitative focus metric.
  - **Signal-to-Noise Ratio (SNR)**: Frequency-domain sensor noise indicator.
  - **Quality Risk Score**: Composite index triage indicator ($S_{\text{risk}} \in [0, 1]$).
  - **Relative Novelty Score**: k-NN latent distance indicating proximity to known clusters.

### Step 5: High-Speed Vector Retrieval via FAISS (Minute 6)
- Click **"Find Similar Images"** or submit a query image in the **Retrieval Studio**.
- Select Top-$k = 5$.
- Observe instantaneous retrieval ($< 1\text{ ms}$ FAISS inner-product search on 384-dimensional DINOv2 embeddings).
- Show ranked micrographs with cosine similarity scores, demonstrating visual semantic alignment across structural phases.

### Step 6: Curator Triage & Decision Persistence (Minute 7)
- Switch role or view to the **Curation Review Queue**.
- Show that images flagged with elevated quality risk or duplicate candidate scores appear automatically in the triage queue.
- Open the **Candidate Review Modal**: Compare side-by-side duplicate candidates.
- Submit a formal curation action:
  - Select **"KEEP"** (or **"MERGE"** / **"REJECT"**).
  - Add justification: *"Micrograph exhibits clean dislocation structures; approved for training corpus."*
- Click **Submit Decision**.

### Step 7: Cryptographic Provenance & Audit Trail (Minute 8)
- Navigate to the **Provenance Audit View**:
  - Display the full chronological chain of custody:
    1. Image uploaded by user `SCIENTIST` (timestamp, IP, file hash).
    2. Quality profile generated by automated pipeline.
    3. Curation decision recorded by curator (decision type, timestamp, rationale).
- Emphasize that provenance records are append-only and immutable.

## 4. Scientific Discussion & Q&A (Minutes 9–10)

1. **Highlight Research Contributions**:
   - DINOv2 self-supervised visual representation achieves **0.9481 Recall@1** on scientific micrographs, outperforming contrastive baselines by $+16.66\%$.
   - FAISS `IndexFlatIP` delivers exact 1.0000 recall with **0.24 ms** latency on 10,000 vectors.
2. **Address Platform Limitations Openly**:
   - Metadata fusion does not improve visual retrieval accuracy under the declared protocol; metadata is used for filtering.
   - Quality-risk scores reflect mathematical contrast/frequency degradation, not physical lens defects.
   - Retrieval performance is domain-dependent and drops on out-of-domain biological TEM images.
